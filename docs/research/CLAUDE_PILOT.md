# Claude development pilot — authorization and protocol

On 2026-09-06 the user requested replacing Ollama with Claude Sonnet/Haiku and explicitly limited paid use to **$5 total, pilot only**. The supplied credential is in a mode-600 file under ignored .runtime; it never enters configuration manifests, model prompts, Git, transport errors or evidence archives. Only the official api.anthropic.com endpoint is used. Redirects, proxy forwarding and automatic generation retries are disabled.

The authenticated Models API confirmed claude-sonnet-5 and claude-haiku-4-5-20251001 availability and structured-output support. Its non-secret response is preserved in artifacts/claude-model-inventory.json. Sonnet 5 uses provider-default sampling (non-default sampling parameters are rejected); Haiku uses temperature zero. Both have thinking disabled and a 2,048-output-token cap. No seed parameter is supported. See [Sonnet specifications](https://platform.claude.com/docs/en/models/sonnet-5/overview) and [Haiku specifications](https://platform.claude.com/docs/en/models/haiku-4-5/overview).

Rates verified 2026-09-06: Haiku input/output $1/$5 per million tokens; Sonnet 5 $2/$10 per million. Sonnet's planned September increase was cancelled according to the official [pricing page](https://platform.claude.com/docs/en/about-claude/pricing). These are standard global API usage rates, not taxes or an account invoice.

A shared SQLite spending ledger reserves the full model input capacity plus maximum output before each generation. Successful responses reconcile that conservative reservation to provider-reported usage. Ambiguous network failures or killed workers retain their full reservation; definite rejected requests settle to zero. The $5 ceiling is shared across both models, all configurations, retries and development runs. The system may stop substantially below $5 because it preserves worst-case headroom. It cannot cancel provider compute already accepted when a local worker is killed.

Pilot scope: first six development variants of the existing development corpus, compared across the six required configurations: rules, naive_single_pass, scoped_single_pass, demo_style_react, v2_no_semantic and v2. Haiku and Sonnet investigator tuples share Sonnet as the isolated semantic verifier. This makes investigator changes explicit while retaining the verifier model. Start with one-case protocol preflight before the complete six-case pilot. All attempts remain in the same spending ledger. No test/challenge claim is made for this pilot. Paid evaluation refuses test/challenge splits and requires a development limit of 1..23 cases. A larger paid study requires new authorization.

The existing scripted held-out experiment at 6604e6f completed 874 case-runs. The Ollama held-out experiment was interrupted at the user's request; its completed and partial outputs remain under artifacts/final-local with interrupted.json. It must not be reported as a completed experiment or silently merged with Claude results. The new provider adapter does not retroactively change the frozen scripted evidence.

Claude uses a supported subset of the schema decoder, while original strict Pydantic constraints remain enforced locally. Refusals, output limits, schema failures and verifier citation failures are visible outcomes. See [structured-output constraints](https://platform.claude.com/docs/en/build-with-claude/structured-outputs). Credentials and private reasoning blocks are excluded from the run trace. Returned usage, request ID, response model, stop reason and billed-token cost are recorded.
