# FF Insights V2 architecture

V2 is a local research harness for one synthetic vendor-bank-change/payment hypothesis. The audited V1 baseline remains in Git at 2a3c28b; the new entry points use core/v2 and do not read a .env. The original Downloads checkout is not an execution dependency.

A SourceRecord has immutable scope, source locator, identity, business object, UTC event/ingestion times and explicit field values. A Snapshot deduplicates exact repeats, rejects conflicting locators, sorts deterministically and hashes the complete source set. CanonicalEvent binds raw JSON, its hash, parser version and snapshot. Model text cannot create a trusted source event.

The case graph builds Event, Actor, AccessRequest, Session, TransactionCode, Table, BusinessObject, FieldChange, PolicyRule and TimeWindow nodes. Every edge cites source events. PRECEDES means strictly earlier within the same actor/session/object chain; it does not establish causality. Claim paths must be contiguous verified edges, and every intermediate event must have been retrieved. Hypothesis-only edges cannot satisfy this obligation.

The hypothesis JSON declares allowed bank fields/tables, payment transactions/status, a one-hour window, seed predicates, benign alternatives and required checks. A deterministic capsule carries its hash/version, scope, source snapshot, selected event IDs/hashes, exact fields, query completeness and resource limits. Raw, original legacy pipe, new quoted pipe, typed JSON, compact typed edges and full hybrid graph formats are available. The legacy formatter loses actor/object/full-date context; the harness does not backfill that information for the model.

A capability fixes tenant, request, snapshot, templates, sources, expiry, row/byte limits and run ID. The gateway alone interprets model queries. Neither model receives arbitrary Elasticsearch DSL, shell, writes, credentials or an outbound-network tool. Memory and Elasticsearch backends use the same filter and pinned-event validation. Search results carry known counts, stable event ordering, truncation, cursor and execution metadata. Elasticsearch uses an explicitly mapped, write-blocked owned synthetic index; verified content is immutable during a run. Search-after pagination uses event time plus event ID as a tie breaker. See [Elastic 8.13 pagination documentation](https://www.elastic.co/guide/en/elasticsearch/reference/8.13/paginate-search-results.html).

The investigator emits a tool request or atomic proposal. The live adapter selects bank/payment IDs and claimed actor/session/object; deterministic compilation attaches field hashes and candidate paths. This attachment never bypasses scope, observed-evidence, join, time or domain validation. The scripted adapter is an observation-based protocol fake. It is useful for testing the harness, not for estimating LLM performance.

Verification checks schema, existence, scope, source hashes, exact cited fields, query provenance, joins, temporal relationships and the hypothesis domain. A contradiction query retrieves related approvals and reversals. A separate-context verifier sees one claim and only its cited fields, without investigator confidence or narrative. The default local experiment uses the same base model for both roles; context isolation is not independence of model errors. Structural failures abstain, contradiction findings abstain, and missing coverage or uncertain semantic support requires review. Severity is a fixed synthetic policy label, never a confidence score.

The parent process enforces the wall-clock deadline and cancellation independently of the worker. The worker tracks attempts, repairs, queries, verifier calls, finalization, rows, bytes and conservative token reservations. The parent terminates only its owned worker process group and records cleanup overhead. It cannot guarantee cancellation of compute already accepted by an external model server. No real-time OS bound or monetary savings claim follows from this implementation.

The exclusive run ledger preserves the input, manifest, hash-chained observable trace and final report. Capsules, model-visible requests, model responses, tool results and validation decisions live in the trace. Private chain-of-thought is neither requested nor retained. Read-only file modes and hashes are tamper-evident on a local filesystem, not independently notarized or WORM storage. Evaluation labels and metrics are appended by a separate evaluator after investigation. Experiment seals cover the per-case results, all ledgers, summaries and protocol.

Feedback uses ACCEPT, ADJUST, REJECT and INSUFFICIENT_DATA with corrected evidence, reason, role and policy version. Collection is an offline interface; no analyst study has occurred. Isotonic and logistic calibration interfaces refuse generator-only labels. No calibrated probability or analyst-priority score is reported.
